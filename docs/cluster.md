# 空间聚集复核线索方法说明

本文档说明 `GET /clusters/scan` 与 `python -m returnatlas scan` 背后的口径。目标是从现有订单地理资料中找出**值得人工复核的异常区域**，而不是产出一张按退货次数着色的地图，也不是给任何住户贴标签。

## 1. 计数单位：订单、申请、联系是三件事

* **暴露**只计实际完成配送的订单（`deliveries.delivered = 1`）。未完成配送的订单不进入分母，也不可能成为事件。
* **事件**是发生过 `action = 退货` 联系的**去重订单**，一张订单最多记一次。
* 一项退货申请可以产生多条联系记录，同一订单也可能有多项申请。报告同时给出联系记录数、申请数和退货订单数，并列出「多次联系/多项申请」的订单 ID；多出来的联系不会被当成多起退货。
* 非退货动作（如咨询）不计事件。

## 2. 分层控制品种与履约周构成

同一退货次数在大小片区含义不同，因此比较的是**实际事件数与期望事件数**，不是原始次数。

* 分层单元为 `品种 × 履约周`（履约周取配送日的 ISO 周）。
* 每个分层的基准退货率 = 该层退货订单数 / 该层完成订单数。
* 任意扫描窗口的期望事件数 μ，是窗口内各订单所属分层基准率的加总（间接标准化）。品种结构或履约周结构不同的片区，期望值会自动不同。
* 可用 `species` 限定品种白名单，用 `week_from` / `week_to` 限定履约周范围；过滤后分层在剩余数据内重建。

## 3. 扫描统计量与搜索网格

* 统计量为分层 Poisson 空间/时空扫描统计量（Kulldorff 型），只检验**单侧高值**（退货偏多），不报告退货异常偏低的窗口。
* 对每个有暴露的位置取圆心，枚举到各位置距离形成的全部离散半径；窗口暴露上限为总期望的 50%，避免无意义的超大窗口。
* 时空扫描额外枚举履约周时间前缀（从研究期第一周起的累计窗）。`spatial_only=1` 时只扫空间窗。
* 线索最少事件数 `min_events` 默认为 2，单点单事件的偶然波动不进入候选。
* 候选线索按 LLR 降序贪心选取、位置互不重叠，最多保留 10 条，再按第 4 节的显著性过滤。

## 4. 与搜索过程匹配的误报控制

扫描位置、尺度、时间窗相当于反复挑选高值，单个窗口的局部 Poisson 检验 p 值会系统性偏小。本服务不报告局部检验，而是：

1. 在**同一套完整搜索网格**上，重复在每个分层内部随机置换订单的事件标签（保持各层事件总数、暴露位置分布与时间结构不变）；
2. 每次置换重新跑全部圆心 × 半径 × 时间窗，记录全局最大 LLR，形成原假设下的最大值分布；
3. 观测窗口的 p 值 = `(1 + 置换中 LLR 不小于该窗口的次数) / (置换次数 + 1)`。

因此 p 值对应的是「在这么大范围搜索后仍出现此高值」的族错误率，而非挑中窗口的局部检验。只有 `p ≤ 0.05` 的互不重叠窗口才作为复核线索输出；报告同时给出原假设 LLR 的 95% 分位阈值、评估窗口总数和过滤前候选数，便于判断「无线索」是因为没有信号还是搜索不足。随机种子 `seed` 固定后结果可复现。

置换检验是随机推断，p 值的最小可分辨率为 `1 / (mc + 1)`；默认 `mc = 399`，正式复核可提高到 999 或更高。

## 5. 地理不确定性如何进入稳定性判断

### 5.1 街道级多候选位置

`locations.candidates` 为每个位置给出带相对权重的候选坐标，权重在该位置内归一。基准分析使用加权质心；稳定性分析按候选权重重复抽样（`realizations` 次，默认 100），每次用抽中的坐标重新扫描，并对每条线索报告：

* `anchor_inclusion_rate`：锚点位置落入匹配窗口的频率；
* `jaccard_mean` / `jaccard_min`：匹配窗口与原线索位置集合的 Jaccard 重合度；
* `detection_rate`：匹配窗口 LLR 仍超过基准 95% 分位阈值的频率；
* `centroid_drift_km_max`：同组位置在不同定位实现下的质心最大漂移；
* `radius_span_km`：匹配窗口半径的波动区间。

### 5.2 服务边界随时间变化

`service_areas` 的边界左闭右开、按版本生效。报告对三种边界情景各跑一次扫描并给出匹配情况：

* `time_varying`（基准）：按订单配送日取当时生效的边界；
* `fixed_earliest`：最早版本边界用于全时段；
* `fixed_latest`：最晚版本边界用于全时段。

边界只用于判断订单质心是否处于当日可达范围（可达性掩码），**不是销量或人口分母**。被边界情景排除的订单数量逐情景披露。

## 6. 无配送不等于无风险

* 没有完成配送订单的位置没有可见暴露，不参与扫描，统一列入 `coverage.locations_without_exposure`，并在解释文字中明确「不得解释为无风险」。
* 过滤条件（品种、履约周）可能使某些位置在当前分析中失去暴露，这些位置同样只进无暴露清单。
* 服务边界之外没有观察资料，结论不外推到边界外。

## 7. 输出与分辨率边界

每条线索包含：锚点与成员位置 ID、定位分辨率构成（街道/路段）、半径与质心（虚构局部平面坐标，单位公里）、时间窗、事件数、暴露订单数、期望事件数、观测/期望比、窗口内外相对风险、搜索校正 p 值、分层构成、全部退货订单 ID 与暴露订单 ID、联系/申请计数、多联系订单 ID、地理定位稳定性与三种边界情景的稳定性。

`POST /cluster-reviews` 可把完整报告连同数据指纹、引用到的配送单、联系记录、位置与服务边界原始记录固化为不可变存档（带 SHA-256 校验），使线索可回溯到具体订单、暴露口径与边界假设。

**分辨率边界**：源地址只定位到街道或路段，所有结论只支持该层级的区域复核。报告不含也不推导任何住户、个人或门牌级标识；坐标是虚构本地平面坐标，不能当经纬度使用。
